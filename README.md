# Система для добавления и чтения постов и комментариев с использованием GraphQL.

### Предворительная настройка проекта:

    - Пройдите по пути \GraphQL_posts\config\config.yaml

    - Выберите интересующий Вас вариант сохранения данных (Укажите PSG или IN_MEMORY в строке TYPE_DB)


### Quick start:
    docker-compose up --build
Перейдите на http://localhost:8081/ для удобства использования
### Завершить работу:
    docker-compose down -v
## Архитекутра проекта:
В основе использовался популярный Github репозиторий, описывающий вариант layout проектов на Golang
`https://github.com/golang-standards/project-layout`

Так же была использованно архитекутра DDD, для разделения модулей проекта по пакетам и работы с каждым модулей по одтельности.
Для этого в папке internal\ расположены основные модули: User, Post, Comment
Внутри модулей располагаются папки service и repositoryPsg, repository. 

В частности как видно папка repository была разделена на 2. Тк по ТЗ необходимо реализовать 2 видо харнения информации.
Соответственно в repository используется In_memory, а в repository PostgreSQL.
Оба репозитория используют одинаковые интерфейсы.

`/api` Папка для работы с GraphQL.
Подробнее: resolver реализует handler. Именно поэтому в этом же пакете были прописаны интерфейсы для работы с service.

`/cmd` Точка входа в программу

`/config` Конфиг файлы проекта

`/docker` Dockerfile программы

`/internal` Модули программы

`/pkg` Работа с библиотеками. Psg, logger, localstorage и тд.

`/test` Автотесты. Запуск автоматический.


## Виды запросов:

- Request:
```

  createUser(input: {
    name: "Георгий",
    surname: "ФамилиюНеПридумал"
  }) {
    id
    name
    surname
  }
}
```

```
    "createUser": {
      "id": 2,

      "surname": "ФамилиюНеПридумал"

  }
}
```

## N+1:
Суть проблемы N+1 заключается в дополнительных запросах

Решение проблемы:

    При запросе к постам ( получение всех постов ) или при запросе к комментариям (получение всех комментариев или связанных с ними)
    Используются JOIN для обьединения двух таблиц. Например в постах, чтобы не делать дополнительные N запрсов для получение информации о
    пользователях, используется JOIN к таблице users и получение данных о пользователях вместе с получением данных о посте.

    Аналогичный метод используется и в получении комментариев.

### Характеристики системы постов:
    •	Можно просмотреть список постов.

    •	Можно просмотреть пост и комментарии под ним.

    •	Пользователь, написавший пост, может запретить оставление комментариев к своему посту.


### Характеристики системы комментариев к постам:
    •	Комментарии организованы иерархически, позволяя вложенность без ограничений.

    •	Длина текста комментария ограничена до, 2000 символов.

    •	Система пагинации для получения списка комментариев.



### Стек:
    •	Система написана на языке Go.
    •	Использование Docker для распространения сервиса в виде Docker-образа.
    •	Реализовано 2 варианта хранение данных: в памяти (in-memory) и в PostgreSQL.
    •	Для логгирования информации используется zap logger
